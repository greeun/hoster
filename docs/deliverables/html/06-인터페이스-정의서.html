06. 인터페이스 정의서

hoster가 바깥 네 곳과 주고받는 업무 협약서와 양식 규격회사 두 곳이 거래를 트기 전에 정해 두는, 서로 무엇을 주고받을지·어떻게 증명할지 적은 문서이다. 칸이 하나라도 어긋나면 접수 자체가 안 된다 — 이 문서는 그 네 협약서를 한 장씩 편다.

대상: packages/cli, templates/workflow.yml.tpl, Cloudflare API, NAS SSH 버전 1.0 작성일 2026-08-13 원문: docs/deliverables/06-인터페이스-정의서.md
지금 보고 있는 곳: 단지 배치도(02번 문서 자산의 축약판) 밖에서 관리사무소로 이어지는 네 개의 화살표 — 로컬 CLI·GitHub Actions·Cloudflare·NAS SSH 각각이 관리사무소(deployer)와 맺는 협약이 이 문서의 대상이다.

시그니처접점 계약 매트릭스 — 4장의 업무 협약서

1층. 회사 두 곳이 거래를 트려면 무엇을 주고받을지, 신분을 어떻게 증명할지, 서류가 틀리면 어떻게 되는지를 협약서 한 장에 정해 둔다. 그리고 양쪽 서식의 어느 칸이 토씨 하나까지 같아야 접수되는지도 못박아 둔다. hoster의 4개 접점도 마찬가지다 — 카드 하단 점선 칸(≡ 원문 일치)이 그 칸이다.

2층 · 기술 상세레포 시크릿 2종 · 토큰 권한
  • 레포 시크릿은 HOSTER_DEPLOY_URL(값: config.deployerUrl = https://hoster.<baseDomain>)과 HOSTER_DEPLOY_SECRET(값: config.hmacSecret) 2종뿐이다.
  • 워크플로 내부의 secrets.GITHUB_TOKEN(GHCR 로그인용)은 Actions가 자동 제공하는 값이라 gh secret set 대상이 아니다.
  • Cloudflare 토큰 요구 권한(README.md): Zone.DNS Edit, Account.Cloudflare Tunnel Edit.

1CLI 커맨드 9종의 지형 — 무엇을 바꾸는가

1층. 9개 커맨드를 같은 크기 카드로 나란히 세우면 성격이 안 보인다. "실행하면 무엇이 바뀌는가" 축으로 세 칸에 나눈다. init은 단지 전체를 처음 여는 부트스트랩아무것도 없는 상태에서 시스템이 스스로 일어서게 만드는 첫 시동 절차 — 여기서는 터널·네트워크·NAS 설정을 한 번에 만드는 것 커맨드이며, 대부분의 커맨드에 플래그커맨드 뒤에 붙여 동작을 살짝 바꾸는 옵션 스위치, 예: --dry-run가 있다. --dry-run은 실제로 저지르지 않고 계획표만 보여주는 드라이런"이렇게 될 것이다"만 미리 보여주고 실제로는 아무것도 바꾸지 않는 예행연습 스위치다. doctor는 무엇도 바꾸지 않고 점검만 하고, env는 set/rm 두 하위 커맨드를 거느린 묶음이다.

2GitHub Actions 연동 계약 — 서식 인쇄와 서명

1층. 템플릿 토큰 치환서식의 빈칸에 실제 값을 인쇄해 채우는 것 — templates/workflow.yml.tpl의 {{...}} 빈칸을 hoster add가 실제 값으로 채운 뒤 레포에 .github/workflows/hoster-deploy.yml로 찍어 낸다. 남은 빈칸이 있으면 "템플릿 토큰 미지정" 예외로 인쇄 자체를 거부한다.

BODY=$(printf '{"project":"%s","image":"%s","sha":"%s"}' \
  "{{PROJECT}}" \
  "{{IMAGE_REPO}}:${{ github.sha }}" \
  "${{ github.sha }}")
TS=$(date +%s000)
SIG=$(printf '%s.%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$DEPLOY_SECRET" -hex | awk '{print $NF}')
HTTP_CODE=$(curl -s -o /tmp/resp.txt -w '%{http_code}' -X POST "$DEPLOY_URL/deploy" \
  -H "content-type: application/json" \
  -H "x-hoster-timestamp: $TS" \
  -H "x-hoster-signature: $SIG" \
  -d "$BODY" --max-time 300)
cat /tmp/resp.txt
[ "$HTTP_CODE" = "200" ] || exit 1
  • 1date +%s000 — 초 단위 epoch에 문자열 000을 이어붙인 ms 근사값(실제 밀리초 정밀도 아님)
  • 2 서명 대상 문자열은 <TS>.<BODY> — 07번 문서 도장 실습기와 같은 공식. $DEPLOY_SECRET = secrets.HOSTER_DEPLOY_SECRET
  • 3 응답 코드가 정확히 "200"이 아니면 워크플로가 exit 1
2층 · 기술 상세이미지 태그 규칙

SHA 태그와 latest 태그를 동시에 push한다:

tags: |
  {{IMAGE_REPO}}:${{ github.sha }}
  {{IMAGE_REPO}}:latest

3Cloudflare API 7개 호출 지도 — 언제 어떤 전화를 거는가

1층. Cloudflare는 터널정문을 열지 않고 안에서 밖으로 미리 뚫어 둔 전용 통로과 DNS/CNAME도메인 이름표를 실제 위치로 잇는 장부을 관리하는 외부 기관이다. hoster는 이 기관에 7가지 전화를 걸며, 어느 커맨드가 언제 어떤 전화를 거는지가 다르다.

2층 · 기술 상세Cloudflare 엔드포인트 전체 표
Base URL: https://api.cloudflare.com/client/v4 (packages/cli/src/cloudflare.ts)
메서드경로용도호출 함수
POST/accounts/{accountId}/cfd_tunnel터널 생성createTunnel
GET/accounts/{accountId}/cfd_tunnel/{tunnelId}/token터널 토큰 조회getTunnelToken
PUT/accounts/{accountId}/cfd_tunnel/{tunnelId}/configurations인그레스 규칙 설정setTunnelIngress
GET/zones/{zoneId}/dns_records?name=…DNS 레코드 정확 일치 조회findDnsRecord (private)
PUT/zones/{zoneId}/dns_records/{id}기존 레코드 갱신upsertDnsCname (존재 시)
POST/zones/{zoneId}/dns_records신규 레코드 생성upsertDnsCname (없을 시)
DELETE/zones/{zoneId}/dns_records/{id}레코드 삭제deleteDnsRecord

findDnsRecord는 type 지정 시(upsert/delete 모두 CNAME으로 좁힘) 결과가 항상 0건 또는 1건이다 — exact 이름 조회비슷한 이름이 아니라 정확히 일치하는 이름 하나만 찾는 방식.

4NAS SSH 인터페이스 — 전용 통로로 상자를 옮기는 법

1층. hoster는 파일을 옮길 때 SFTP/SCP를 쓸 수 없다. 대신 tar over ssh디렉터리를 tar로 묶어 SSH 연결의 표준입력으로 그대로 흘려보내고, 반대편에서 다시 풀어내는 방식 — 로컬에서 tar로 묶어 SSH stdin으로 흘려보내고, NAS 쪽에서 받아 다시 풀어낸다.

2층 · 기술 상세shQuote 인용 규칙 · 전송 절차 
export function shQuote(value: string): string {
  return `'${value.replace(/'/g, "'\\''")}'`;
}

packages/cli/src/shell.ts — 값을 작은따옴표로 감싸고, 내부의 작은따옴표는 '\''(닫는 따옴표+이스케이프된 리터럴 따옴표+여는 따옴표)로 치환하는 POSIX 인용셸에 값을 안전하게 넘기려고 따옴표로 감싸는 표준 방식 기법.

  • 적용 원칙(commands/init.ts 주석): NAS/로컬 셸 명령에 보간되는 모든 값(NAS host/user/port 포함)이 예외 없이 shQuote를 거친다.
  • substitutePlaceholders(template, values)는 ${KEY} 형태 자리를 shQuote(value)로 치환하되, String.replaceAll 대신 split/join을 써서 교체 문자열의 $&/$$가 특수 패턴으로 해석되는 것을 막는다.
  • init에서는 STATE_DIR_CMD(mkdir -p /volume1/docker/hoster/state/env) 실행 후 stack/를 /volume1/docker/hoster-tmp로 전송, 이어 cp -a + rm -rf로 최종 위치(/volume1/docker/hoster)에 반영한다.

1층. 정규식 자체의 해부(어떤 문자를 허용/거부하는가)는 03번 문서의 몫이다. 여기서는 같은 이름의 값이 CLI 파일과 deployer 파일 중 어디서 검사되는지, 그리고 양쪽 모두에서 검사되어야 하는 값이 무엇인지에 집중한다.

8이 문서가 말하지 않는 것 / 확인 못 한 것

1층. 협약서 규정집에 없는 항목은 "없다"고 우기지 않고, "이 원문은 답하지 않는다"고 빈 도장칸으로 남긴다.

빈 도장칸

각 커맨드의 표준출력 정확한 포맷 문자열(줄바꿈·공백 등)은 다루지 않는다 — 판정 흐름과 필드만 다룬다.

빈 도장칸

Cloudflare 응답 스키마의 전체 필드 목록은 다루지 않는다. success/result/errors 등 판정에 필요한 부분만 옮겼다.

확인 못 함

env --redeploy가 POST /deploy를 직접 호출하는 것 외에, CLI가 배포를 직접 트리거하는 다른 경로는 원문에 없다. "CLI로 수동 배포"가 더 있는 것처럼 단정하지 않았다.

다른 문서 몫

서명 검증의 내부 순서(길이 비교 우선·timingSafeEqual·5분 허용 오차)는 07번이, 정규식 5종의 문자 단위 해부는 03번이 다룬다.
