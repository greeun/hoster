08. 테스트 결과 보고서

hoster를 지은 뒤 관리사무소가 직접 돌린 검사 167항목의 성적표다. 검사 대상은 앱을 담아 나르는 컨테이너내용물이 무엇이든 규격이 같아 어디서든 그대로 실어 나를 수 있는 표준 상자를 새로 들이는 절차, 문제가 생겼을 때 이전 상자로 되돌리는 롤백받은 물건이 잘못됐을 때 바로 전에 있던 물건으로 되돌리는 것, 그리고 그 과정에서 신분을 확인하는 HMAC우리 둘만 아는 인주로 찍는 도장 — 본문과 시각을 섞어 계산하는 서명값 서명까지 아우른다. 15개 검사 구역(파일) 전부 통과했고 불합격은 0건이지만, 검사원이 실제로는 모형진짜 NAS·진짜 Cloudflare 대신 가짜로 흉내 낸 대역을 놓고 검사한 경우으로 검사한 구역도 있다. 이 문서는 어디를 진짜로 봤고 어디를 아직 못 들어가 봤는지를 숨기지 않는다.

03

검사원 6명, 각자 얼마나 실물을 보고 판정하는가

같은 "테스트"라도 성격이 다르다. 왼쪽일수록 부품 하나만 떼어 보는 검사, 오른쪽일수록 실제 물류·통신까지 재현해 보는 검사다.

④ 오케스트레이션러너(runner) 주입ssh·docker 명령을 실제로 실행하는 대신, "이런 명령이 이 순서로 호출됐다"만 기록하는 대역 실행기로 바꿔 끼우는 것으로 단계 흐름 재현

⑥ 실daemon 검증 — 자동화 테스트 없음 실제 Docker 데몬·SSH·gh CLI를 쓰는 자동 테스트는 이 저장소에 없다. docker.test.ts는 dockerode를 vi.fn()으로 모형 처리한다. 실물 확인은 사람이 리뷰 과정에서 수동으로 했다(예: 커밋 420281e 메시지가 언급하는 "reviewer's stopAndRemove THREW: 304" 재현).

🖋 1층 — 왼쪽 검사원은 부품 하나만 뜯어보고, 오른쪽으로 갈수록 실제 배송 과정을 통째로 재현해서 검사한다. 가장 오른쪽 "실물 검사"는 이번 자동 채점표에는 없고, 사람이 직접 현장을 확인했다.

2층 기술 상세 펼치기

모킹(mock)과 페이크(fake)진짜 대신 세워두는 대역 — mock은 "이 함수가 불렸는지만" 확인하는 얇은 대역, fake는 상태를 실제로 흉내 내는 두꺼운 대역의 차이가 ④/⑤를 가른다: orchestrator.test.ts의 makeFakeDockerode(29-84행)는 컨테이너의 running/image 상태를 실제로 추적하는 페이크이고, docker.test.ts는 dockerode 메서드 호출 여부만 보는 목이다.

의존성 주입실제 실행기 대신 테스트용 실행기를 갈아 끼울 수 있게 만들어 둔 구조 및 러너(runner) 주입ssh·docker 명령을 실제로 실행하는 대신, 테스트가 "이런 명령이 이 순서로 호출됐다"만 기록하는 대역 실행기로 교체하는 것이 ④를 가능하게 한다.

  const p3 = orchestrator.execute(deployC)   // p2를 밀어내고 "최신 대기"가 됨

  • 실제 코드가 아니라 재구성입니다 — 원문(08번 문서)에 인용된 줄 범위(172-187행)의 시나리오 설명을 코드 형태로 옮긴 것이며, 저장소의 실제 소스를 그대로 복사한 것이 아닙니다.

07 · 이 문서가 말하지 않는 것

아직 들어가 보지 못한 구역 5곳

정직성 노트 — 167개 전부 통과했다는 것은 "코드가 스스로 일관된다"는 뜻이지, "실제 NAS·실제 Cloudflare·실제 GitHub에서 검증됐다"는 뜻이 아니다. 아래 5곳은 자동 채점표 밖에 있다.

점검한 구역 vs 못 간 구역 — 같은 격자 위에 겹쳐 보기

§2 점검표의 ⚠ 표시 4칸이 아래 목록과 그대로 대응한다. 다섯 번째(NAS 아키텍처)는 특정 파일이 아니라 빌드 조건에 걸린 가정이라 격자 밖에 별도로 둔다.

실제 NAS SSH/docker 실행

자동화 테스트는 러너 주입으로 대체 (nas.test.ts). 위임처: docs/e2e-checklist.md

실제 Cloudflare API 호출(터널/DNS)

fetchFn 주입으로 대체 (cloudflare.test.ts). 위임처: docs/e2e-checklist.md

실제 GitHub(gh CLI, Actions 워크플로우 실행)

러너 주입으로 대체 (runAdd.test.ts). 위임처: docs/e2e-checklist.md

실제 Docker 데몬

docker.test.ts는 dockerode를 vi.fn()으로 목 처리. 실daemon 검증은 리뷰 과정에서 사람이 수동 수행.

NAS 아키텍처 가정 (격자 밖 — 특정 파일이 아닌 빌드 조건)

commands/init.ts:108의 이미지 빌드가 --platform linux/amd64로 고정 — amd64 NAS를 전제한다. arm64 NAS는 미검증.

🖋 1층 — 검사원이 다섯 군데는 아직 진짜 현장 문을 열어 보지 못하고, 그 자리를 흉내 낸 모형으로 대신 확인했다는 뜻이다. 대신 확인해 줄 다음 단계(위임처)가 정해져 있다.
