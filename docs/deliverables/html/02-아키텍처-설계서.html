아키텍처 설계서

앵커 비유: 단지 배치도 — 정문(호스트 포트)은 잠겨 있고, 물건도 손님도 후문 전용 통로로만 들어옵니다. 이 문서는 hoster가 사는 "단지"의 배치를 한 장에 그리고, 그 위에 배포 경로와 주민 통행 경로 두 가지를 겹쳐 봅니다.

0처음 보는 말 — 먼저 풀어둡니다

본문에서 이 말들을 다시 만나면 전부 여기 적은 뜻입니다. 여기서 한 번 풀어두고, 본문에서는 다시 설명하지 않습니다.

컨테이너 — 내용물이 무엇이든 규격이 같아 어디서든 그대로 옮길 수 있는 표준 이사짐 상자
이미지 — 컨테이너를 찍어내는 원판. 같은 이미지면 언제 열어도 내용물이 같음
레지스트리(ghcr.io) — 포장된 상자를 맡아 두는 물류 창고
터널 — 정문을 열지 않고 안에서 밖으로 미리 뚫어 둔 전용 통로
리버스 프록시(Traefik) — 동·호수 팻말을 보고 배달할 세대를 정해주는 경비실 안내데스크
DNS/CNAME — 간판 주소(도메인)를 실제 배송지에 연결해 두는 주소록 등록
HMAC(서명) — 우리 둘만 아는 인주로 찍은 도장. 도장이 같아야 접수됨
타임스탬프 허용 오차 — 접수증 시각이 너무 오래됐으면(5분 초과) 반려하는 규칙
헬스체크 — 새 설비가 실제로 불이 들어오는지 확인하는 점검
롤백 — 새 물건에 하자가 있으면 원래 물건을 다시 꺼내 놓는 것
배포 큐 — 접수창구에 밀려드는 요청을 순서대로 처리하는 대기줄
부트스트랩 — 관리사무소를 처음 여는 개소(開所) 준비 절차
docker label — 컨테이너 문 앞에 붙이는 호수 팻말. 경비실이 이걸 보고 배달 여부를 정함
bridge 네트워크 — 같은 단지 안에서만 통하는 내부 배선망
external 네트워크 — 단지 준공 때 미리 깔아 둔 배선망. 나중 공사가 새로 깔지 않고 그대로 씀
인그레스(ingress) — 후문으로 들어온 것을 어느 부서로 넘길지 정하는 접수 규칙표
아웃바운드 연결 — 안에서 밖으로 먼저 거는 전화. 밖에서 안으로 거는 전화는 애초에 받지 않음
WAL(저널 모드) — 장부에 바로 옮겨 적기 전에 먼저 써 두는 임시 메모장
볼륨 마운트 — 관리사무소 서랍(컨테이너 내부 경로)을 실제 창고 캐비닛(NAS 디스크 경로)에 그대로 연결해 두는 것
restart policy(unless-stopped) — 정전이 나도 사람이 끄지 않는 한 저절로 다시 켜지는 자동복구 규칙

1시스템 구성도 — 단지 배치도

정문은 잠겨 있고, 물건도 손님도 후문 전용 통로(터널)로만 들어옵니다. 아래 배치도는 이 시리즈 전체가 공유하는 자산입니다.

컴포넌트 6종 — 누가 어디에 사는가

2네트워크 설계 — "포트 없음" 원칙

단지는 정문을 아예 열지 않습니다. 손님도 물건도 후문 전용 통로 하나로만 드나듭니다.

3터널 인그레스 2규칙 + 404 폴백

후문으로 들어온 것도 아무 데나 배달되지 않습니다. 팻말(호스트명)을 보고 정확히 두 곳 중 하나로만 갑니다.

4기술 선정 사유

모든 결정은 하나의 뿌리에서 갈라져 나옵니다 — NAS의 과거 이력과 "정문을 열지 않는다"는 방침.

결정 항목선택대안사유
이미지 빌드 위치GitHub ActionsNAS 자체 빌드NAS bridge 네트워크 과거 외부 통신 불가 이력

5배포 시퀀스 12단계

POST /deploy 접수부터 다음 접수를 받을 준비까지, 관리사무소가 처리하는 순서표입니다.

6컨테이너 교체 전략 — stop-before-start와 그 대가

설비실 작업 순서표 — 낡은 설비를 옆으로 빼서 먼저 끄고, 새것을 켜고, 불이 들어오는지 봅니다. hoster는 무중단 배포가 아닙니다 — 교체 중 실제로 응답하지 않는 시간이 있다는 것을 감추지 않고 스스로 밝힙니다.

7상태 관리 — 요약

장부(DB)가 실제로 어디에 있는지만 여기서 확인합니다. 장부 안쪽 내용은 05번 문서가 다룹니다.

8이 문서가 말하지 않는 것 / 확인 못 한 것

축소하거나 미화하지 않습니다. 이 두 가지는 이번 범위에서 확인되지 않았습니다.
