# hoster 요구사항 정의서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 프로젝트명 | hoster |
| 작성일 | 2026-08-13 |
| 버전 | 1.0 |

## 배경

- Synology NAS(Container Manager)를 Vercel처럼 사용하는 셀프호스팅 배포 시스템 부재.
- GitHub push만으로 Docker 이미지 빌드·배포·라우팅이 자동화되는 도구 필요.
- NAS 접속·빌드 환경에 다음 제약 존재 (상세는 "제약사항" 절): SSH 2222 고정, sudo docker 절대경로, scp 불가, bridge 외부 통신 불가 이력.

## 목표

- GitHub 레포에 push 시 GitHub Actions가 Docker 이미지를 빌드해 ghcr.io에 push.
- NAS 상주 deployer가 이미지를 pull하여 컨테이너로 교체 배포하고 헬스체크·실패 시 자동 롤백 수행.
- Cloudflare Tunnel을 통해 포트포워딩 없이 `<프로젝트>.example.com` 공개 URL로 서비스.
- `hoster` CLI(로컬 Mac 실행)로 NAS 부트스트랩, 레포 등록, 배포 상태 조회·롤백·환경변수 관리를 수행.

## 기능 요구사항

### 배포 파이프라인

| ID | 요구사항 | 구현 위치 |
|---|---|---|
| FR-01 | GitHub push 시 GitHub Actions가 `docker/build-push-action`으로 이미지를 빌드해 `ghcr.io/<owner>/<repo>:<sha>`, `:latest` 태그로 push | `templates/workflow.yml.tpl` |
| FR-02 | 빌드 완료 후 GitHub Actions가 `x-hoster-timestamp`/`x-hoster-signature`(HMAC-SHA256) 헤더를 붙여 `POST https://hoster.<baseDomain>/deploy` 호출 | `templates/workflow.yml.tpl` |
| FR-03 | deployer가 모든 요청(단, `/healthz` 제외)에 대해 HMAC 서명과 타임스탬프(허용 오차 5분)를 검증 | `packages/deployer/src/hmac.ts`, `packages/deployer/src/app.ts` |
| FR-04 | 프로젝트별 배포 요청을 큐로 순차 처리 — 실행 중일 때 새 deploy가 오면 대기 중이던 이전 deploy는 `skipped` 처리, rollback은 스킵 없이 순서대로 대기 | `packages/deployer/src/orchestrator.ts` (`enqueue`) |
| FR-05 | 이미지 pull → 기존 컨테이너를 `hoster-<project>-old`로 rename 후 정지 → 새 이미지로 `hoster-<project>` 기동(Traefik label 자동 부착) | `packages/deployer/src/orchestrator.ts` (`swapContainer`), `packages/deployer/src/docker.ts` (`run`) |
| FR-06 | 신규 컨테이너 헬스체크: `http://hoster-<project>:<port><healthPath>`, 1초 간격 재시도, 기본 타임아웃 60초, 응답 코드 400 미만이면 통과 | `packages/deployer/src/docker.ts` (`healthCheck`) |

| FR-09 | `POST /rollback/:project` — 직전 이미지로 동일한 swap·헬스체크 절차 재실행, 성공 시 현재/직전 이미지 스왑 | `packages/deployer/src/orchestrator.ts` (`doRollback`), `packages/deployer/src/app.ts` |

## 제약사항

NAS 환경 제약 (실제 구현 기준):

- SSH 접속: `ssh -p 2222 admin@192.168.1.100`(키 `~/.ssh/id_ed25519`) — 포트 2022는 배너만 응답할 뿐 접속 불가, 실제 포트는 2222 고정.
- Tailscale 경유 접속 가능: `newt-tegu.ts.net`.
- NAS docker 명령은 `sudo -n /usr/local/bin/docker` 절대경로로만 실행 — NOPASSWD 권한이 docker 바이너리에만 부여됨.
- SFTP/scp 비활성화 — 파일 전송은 tar over ssh만 가능(`tar -cf - <dir> | ssh ... 'tar -C ... -xf -'`).
- NAS docker bridge 네트워크(`hoster-net`)에서 과거 외부 통신 불가 이력 확인됨 — `hoster init` 11단계에서 `alpine:3.20 wget`으로 외부 HTTP 통신을 진단하며, 실패해도 경고만 출력하고 계속 진행하지만 무시 가능한 실패는 아님(cloudflared 자체가 외부 통신 필요, 실패 시 12단계 healthz도 반드시 실패).
- deployer 이미지는 NAS에서 빌드하지 않음 — 로컬 Mac에서 `docker buildx build --platform linux/amd64 --load` 후 `docker save | gzip | ssh ... 'gunzip | sudo -n /usr/local/bin/docker load'`로 전송.
- NAS 아키텍처는 `linux/amd64`(x86_64) 고정 전제 — `hoster init` 실행 전 `uname -m` 확인 필요.
- NAS 스택 경로 고정: `/volume1/docker/hoster/`(상태 디렉터리 `/volume1/docker/hoster/state/env`).
- 컨테이너 이름 규칙 `hoster-<project>` 고정, `<project>-old`는 스왑 중에만 존재.
- `hoster-net`은 `external: true`로 선언 — `hoster init`이 사전 생성해야 하며 compose가 자체 생성하지 않음.
- Container Manager 설치, docker 24.0.2 확인됨(spec 기준). DSM 웹 UI 포트는 15000(hoster 자체와는 별개, 참고 정보).
- `hoster add`의 `--branch`는 영숫자와 `. _ / -`만 허용, `--project`는 소문자/숫자/하이픈·63자 이하·첫 글자 영숫자로 제한 — 두 값 모두 workflow 템플릿에 YAML 문자열과 셸 이중따옴표 문자열로 그대로 삽입되기 때문.
- `hoster init` 재실행 시 `HMAC_SECRET`이 새로 생성됨 — 이미 등록된 레포의 `HOSTER_DEPLOY_SECRET`은 이전 값으로 남아 무효화되므로 재동기화 필요.

## 범위 제외

spec "범위 제외 (YAGNI)" 절 기준:

- 웹 대시보드(추후 필요 시 deployer API 위에 추가 가능).
- 멀티 유저/팀 기능.
- PR 프리뷰 배포.
- 커스텀 도메인(`example.com` 외) — 구조상 가능하나 1차 범위 제외.
- HTTPS 인증서 관리 — Cloudflare가 엣지에서 처리, 터널 내부는 HTTP.

최종 미구현 항목(코드 확인 결과, spec/plan에는 언급되었으나 실제 구현 없음):

- host 네트워크 폴백 — spec "위험 요소와 대응"에 `hoster-net` 외부 통신 불가 시 대응책으로 "앱을 host 네트워크 + 고유 포트(18100부터 자동 할당)로 실행" 명시되어 있으나, `NetworkMode: host`·`host.docker.internal`·포트 자동 할당 로직이 코드 어디에도 없음(`packages/deployer/src/docker.ts`는 `NetworkMode: this.network`만 사용).
- `hoster init --repair` — spec "위험 요소와 대응"에 컨테이너 자체 장애 대응으로 언급되었으나, 실제 CLI(`packages/cli/src/index.ts`)의 `init` 커맨드 옵션은 `--dry-run`/`--stack-dir`/`--reuse-tunnel`뿐이며 `--repair`는 없음.
- `healthPath`/`containerPort` CLI 플래그 — deployer의 `POST /projects`는 `containerPort`/`healthPath`를 받아 기본값(3000, `/`)을 override할 수 있으나(`packages/deployer/src/app.ts`), `hoster add`는 이 값을 지정하는 옵션을 노출하지 않고 `branch`만 전달함(`packages/cli/src/commands/add.ts`의 `registerProject` 호출, `packages/cli/src/index.ts`의 `add` 커맨드 옵션 목록).
