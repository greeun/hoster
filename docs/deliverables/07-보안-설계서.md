## 3. 인증 설계 (HMAC-SHA256)

- 서명식: `HMAC-SHA256(secret, "${timestampMs}.${body}")` → hex 인코딩
  - 서버: `packages/deployer/src/hmac.ts:3-4` (`signPayload`)
  - 클라이언트: `packages/cli/src/hmac.ts:3-4` (동일 로직 독립 구현)
- 요청 헤더: `x-hoster-timestamp`, `x-hoster-signature` (`packages/cli/src/client.ts:26-29`, 서버 수신측 `packages/deployer/src/app.ts:50-51`)
- body 처리: `GET`/`DELETE`는 빈 문자열로 서명(`app.ts:52`)
- 검증(`packages/deployer/src/hmac.ts:7-29`):
  - `Number.isFinite(timestampMs)` 아니면 즉시 실패(`hmac.ts:18`)
  - `Math.abs(nowMs - timestampMs) > maxSkewMs` 이면 실패 — 재전송 방지, 기본 `maxSkewMs = 300_000`(5분, `hmac.ts:17,19`)
  - 서명 hex 파싱 실패 시 예외 없이 `false` 반환(`hmac.ts:22-26`)
  - 길이 비교 후 `timingSafeEqual`로 비교(`hmac.ts:27-28`) — 타이밍 공격 방지
- 시크릿 생성: `randomBytes(32).toString('hex')` (`packages/cli/src/commands/init.ts:308-309`), 256비트 엔트로피, `hoster init` 1회 실행 시 자동 생성

## 5. 시크릿 관리

- 생성
  - `HMAC_SECRET`: `randomBytes(32).toString('hex')` (`commands/init.ts:308-309`)
  - Cloudflare API Token / GHCR PAT: `askHidden()` 프롬프트 입력(터미널 echo 없음)
- 저장 위치별 권한
  - NAS `.env`(`/volume1/docker/hoster/.env`): `printf ... > .env && chmod 600 .env` (`commands/init.ts:53-56`)
  - deployer `.env`(프로젝트별, `PUT /env`): `writeFileSync(..., { mode: 0o600 })` 후 `chmodSync(file, 0o600)`로 재강제 — 기존 파일 덮어쓸 때 mode 옵션이 무시되는 것을 보완(`packages/deployer/src/app.ts:170-177`)
  - 로컬 CLI 설정(`~/.hoster/config.json`): `writeFileSync(..., { mode: 0o600 })` + `chmodSync(path, 0o600)` (`packages/cli/src/config.ts:25-31`)
- 전달 경로
  - GitHub Actions 시크릿: `gh secret set HOSTER_DEPLOY_URL / HOSTER_DEPLOY_SECRET --repo <repo>`, 값은 argv가 아닌 stdin으로 전달 — `ps` 등으로 노출 방지(`packages/cli/src/commands/add.ts:71-73` 주석, 213-226 실사용)
  - NAS `.env` 작성: `TUNNEL_TOKEN`/`HMAC_SECRET`/`GHCR_PAT`를 `substitutePlaceholders`로 `shQuote` 인용 후 원격 `printf`에 삽입(`commands/init.ts:339-344`)
  - deployer 프로세스 환경변수: `stack/docker-compose.yml:30-31` (`HMAC_SECRET=${HMAC_SECRET}`, `GHCR_PAT=${GHCR_PAT}`)
- 로그·에러 비노출 원칙
  - `planInit()`은 시크릿을 인자로 받지 않는 순수 함수 — dry-run 출력에 실제 값이 섞일 수 없음(`commands/init.ts:42-45` 주석, `init.test.ts:82` "시크릿은 플레이스홀더로만 존재하고 실제 값이 노출되지 않는다")
  - `printRecoveryNote()`는 진행 상태(`stackTransferred`/`envWritten`/`configSaved`)만 기록, 시크릿 값 자체는 담지 않음(`commands/init.ts:210-236` 주석)
  - Cloudflare API 에러 메시지에 `apiToken` 미포함 — 토큰은 요청 헤더에만 존재(`packages/cli/src/cloudflare.ts:32-34` 주석, `cloudflare.test.ts:158` "API 토큰은 에러 메시지에 노출되지 않는다")

## 6. 명령 실행 안전

- `shQuote`: POSIX 표준 작은따옴표 인용, 내부 작은따옴표는 `'\''`로 치환(`packages/cli/src/shell.ts:7-9`)
- `substitutePlaceholders`: `${KEY}` 치환 시 `String.replaceAll` 대신 `split`/`join` 사용 — 교체 문자열에 `$&`/`$$`가 포함돼도 특수 패턴으로 해석되지 않음(`shell.ts:14-20`, `shell.test.ts:46-49`로 검증)
- 보간 불변식: "Nas.exec/docker는 remoteCmd를 셸 인자로 그대로 넘기므로 호출부에서 보간되는 모든 값은 반드시 이 헬퍼를 거쳐야 한다" — NAS host/user/port도 예외 없음(`shell.ts:1-3`, `commands/init.ts:48-51` 주석)
- `gh secret set` 값은 stdin으로 전달, argv 미사용(`commands/add.ts:71-73`)
- sudo 범위: `sudo -n /usr/local/bin/docker` — 절대경로 docker 바이너리 한정, `-n`(비대화형, 암호 프롬프트 발생 시 즉시 실패)(`packages/cli/src/nas.ts:78`, `commands/init.ts`의 모든 docker 호출에 일관 적용)

## 7. 발견·수정된 취약점 이력

| 취약점 | 심각도 | 수정 커밋 |
|---|---|---|
| `/env/:project` 경로 순회 — hono가 route param을 `decodeURIComponent`하여 `%2F`가 `/`로 해석, `envDir` 밖에 파일 쓰기 가능(`/env/..%2F..%2Fx`) | Critical | `45c2e2f` |
| env 값에 CR/LF 삽입 가능(.env 파일 인젝션) | High | `45c2e2f` |
| `POST /projects` domain 미검증 → Traefik 라우터 라벨(백틱/괄호)에 그대로 삽입 | High | `45c2e2f` |
| env 파일 0644로 생성/유지(시크릿 포함 파일 권한 과다) | Medium | `45c2e2f`, `02d84cd`(기존 파일 덮어쓰기 시 0600 미적용 보완) |
| 오케스트레이터 `running` 락 영구 고착 — `recordDeployment` 등에서 예외 발생 시 락 해제 안 됨, 이후 해당 프로젝트 배포 전부 정지 | High | `2eba716` |
| `rollback()`이 큐를 무시하고 진행 중인 `deploy`와 동시 실행 | High | `2eba716` |
| rollback 중 docker 에러가 unhandled rejection으로 전파 | Medium | `2eba716` |
| Docker 304(이미 정지됨)를 404와 별개로 무시하지 않음 — 롤백 경로가 `stopAndRemove`에서 중단되어 `-old` 컨테이너가 영구 잔류, 이후 배포 전부 실패 | High | `420281e` |
| Docker 304 on start 미무시 — 롤백 후 `start()`가 던지는 304가 실제 원인(데몬 오류)을 가림 | Low | `2e04ed1` |
| Traefik 등록 해제용 `stop(oldName)` 호출이 롤백 보호 try 블록 밖에 위치 — 404/304 아닌 에러 발생 시 `run()`과 롤백(rename+start) 모두 미실행, 서비스가 `-old` 이름으로 완전히 멈춤 | High | `dfa8835` |
| `docker logs`의 멀티플렉스 스트림 8바이트 헤더 미제거 — `hoster logs` 출력에 제어 바이트 혼입 | Low | `420281e` |
| NAS 접속정보(host/port/user)가 `sshTarget`/`sshPrefix` 구성 시 `shQuote` 미적용 — 보간값 전체 이스케이프 불변식의 유일한 예외 | High | `e07bfc8` |
| `parseGitHubRepo`가 owner/repo 문자를 `[^/]+`(슬래시만 배제)로만 제한 — 조작된 origin 리모트로 `workflow.yml.tpl`에 YAML/셸 주입 가능 | High | `4bcfe43` |
| `deleteDnsRecord`가 type 필터 없이 name만으로 조회·삭제 — 동일 이름의 다른 타입 레코드(예: TXT)를 대신 삭제하고 CNAME은 남기는 오작동 가능 | Medium | `4bcfe43` |

## 8. 잔여 위험

| 항목 | 내용 |
|---|---|
| HMAC 시크릿 단일 공유 | `hmacSecret` 하나를 CLI 로컬 설정(`~/.hoster/config.json`)과 각 GitHub 저장소의 `HOSTER_DEPLOY_SECRET`(`commands/add.ts:220-226`)이 동일하게 공유. 프로젝트별/발신자별 키 분리 없음 — 저장소 하나의 시크릿 유출이 전체 deployer API 위조로 이어짐 |
| `docker.sock` 마운트 | deployer 컨테이너에 `/var/run/docker.sock:/var/run/docker.sock`을 rw로 마운트(`stack/docker-compose.yml:35-37`) — 사실상 NAS host의 root 권한과 동급 |
| 컨테이너 root 실행 | `packages/deployer/Dockerfile`에 `USER` 지정 없음 — 기본 root로 실행 |
| 터널 충돌 정규식 휴리스틱 | `TUNNEL_NAME_CONFLICT_RE = /already exists|duplicate/i`(`commands/init.ts:199`)는 Cloudflare 응답 문구가 문서화되지 않아 운영 관찰 기반으로 좁게 매치 — 매치 실패 시 원본 에러는 보존되나, 오탐/미탐 가능성은 정규식 특성상 완전히 배제되지 않음 |
